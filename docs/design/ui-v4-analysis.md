## 2. 设计方案（建议）

### 2.1 入口密码锁屏

- 形式：**5 位图形序列**，按顺序点选 三角形 / 方形 / 圆形；顶部 5 个圆点显示输入进度；左上 X 退出应用；输错时圆点抖动并清空，长按任意图形可清空重输。
- 三个图形用三种低饱和度颜色填充，深色底上易区分又不刺眼：三角形=薄荷绿 #6EE7C7、方形=雾蓝 #7AA2F7、圆形=暖橙 #F2B880。颜色固定（不随主题变），保证肌肉记忆。
- 忘记图案：不提供找回，**在手机端重设后重新同步**；手环端可「清除本地数据并重新同步」（Q1 确认）。
- 防暴力：连续错误 5 次锁 30 秒，之后每次再加 30 秒（不设上限，按实现递增）；错误计数存 storage，冷启动不清零。图案不明文保存，只存 salt + PBKDF2-SHA256(规范化序列，如 TSCST) 的结果（默认 1200 次，迭代次数随 pin 载荷下发，见协议文档）。
- 安全边界要说清：3 种图形 × 5 位 = **243 种组合**，只适合挡「随手拿到手环的人」与肩窥；它不是强密码，**不能拿来当静态加密的密钥**。若以后做静态加密，密钥由手机端生成/下发，而不是从图案派生。
- 锁定时机（v2.0 实现）：冷启动必须解锁；应用 onShow 时若距上次解锁超过 2 分钟则重新上锁（若 Vela 生命周期不可靠，至少保证冷启动锁）。
- 可选增强：每次解锁随机打乱三个按钮的位置（防位置记忆/指纹痕迹），但会牺牲盲操，默认关闭；常在外面输入时可打开。
- 草图里的 △□○ 现在就是密码本身，不再按数字键盘占位理解。

### 2.2 主界面

- 保持无顶栏、3 条/页；每行仍是「issuer + 账号小字 + 大号验证码 + 剩余秒 + 进度条」。
- 右侧 56px 功能条（自上而下）：
  1. **A-Z 圆钮**：打开全屏网格；筛选生效时圆钮显示当前字母（如 S）并高亮；未筛选时显示 A-Z。
  2. 圆钮下方小字：**当前筛选的账号数**（未筛选时显示账号总数）。对应草图里的 "1."；如果你原意是别的（如字母/数字切换），见 Q3。
  3. 页码 2/11（按筛选后的列表计算）。
  4. **菜单**按钮（替代原来只能右滑唤出菜单）。
- 手势保留为快捷方式：上/下滑翻页、右滑开菜单、左滑退出；不再作为唯一入口。
- 无连接状态小圆点（沿用你的要求）；同步入口放到菜单。

### 2.3 全屏字母网格

- 4 列 × 4 行，整屏铺满，单格约 116×73，远大于 44px 触控下限。
- 共 3 页：
  - P1：A–P
  - P2：Q R S T / U V W X / Y Z 0 1 / 2 3 4 5
  - P3：6 7 8 9 / # 全部 / 空白（空白格保留，不显示无效内容）
- **上下滑动翻页**（草图已否定左右翻页），底部 3 个圆点指示当前页；X 或右滑关闭。
- 每格右下角保留**账号数小字**（0 置灰）；当前筛选字母用薄荷绿描边；无账号的字母整体置灰但仍可点（点了以后列表为空，可再选「全部」）。
- 「全部」放在 P3 第 2 行第 2 格，清空筛选。
- 筛选范围仍是全部账号（忽略分类），首字母取 issuer，空则账号名，非 A–Z/0–9 归 #（沿用 v1.0.4 规则）。

### 2.4 详细条目

- 顶部：返回 + 服务名（如 steam）+ 一行小字「来自 Bitwarden · 今天 18:42 同步」。
- 字段：
  - **用户名**：对应现有的 accountName（Stratum 的 Username / Bitwarden 的 login.username），不需要新增字段。
  - **密码**：新增可选字段 password，来自 Bitwarden 的 login.password；Stratum 导出没有密码，显示「未导入密码」。
  - **验证码**：大号 TOTP/Steam 码 + 剩余秒 + 进度条；Steam 仍是 5 位字母数字。
- 密码默认遮罩为 ••••••••，点按显示 10 秒后自动恢复；页面内不做复制（手环没有剪贴板），但支持**长按临时放大**，方便对着手机/电脑输入。
- 手环不提供键盘编辑；修改用户名/密码在手机端完成（本期是否支持见 Q7）。

### 2.5 菜单

建议 4 项（草图 2 项 + 同步 + 退出）：

1. **入口密码**：设置 / 修改 / 关闭入口锁（关闭时要求先验证旧密码）。
2. **立即同步**：向手机端发 mfa_sync_request，手机 App 在前台时推送最新账号；替代原「请求同步」入口。
3. **关于**：版本、构建号、签名证书 SHA-256 指纹、开源许可（Stratum 格式参考、BandOTP 思路致谢）。
4. **退出**：关闭腕证返回表盘（等同锁屏的 X）。

## 3. 数据、协议与安全影响

### 3.1 数据模型

只新增一个字段即可（username 继续复用 accountName）：

    WristKeyAccount += password: String = ""   // 可选，<= 128 字符，空 = 未导入

- BitwardenImporter：保留 login.password；仍只支持未加密导出。
- StratumImporter：password 为空；Username 继续映射 accountName。
- band accountModel：校验 password 长度/字符，允许空；storage 快照版本 +1 并做迁移（老数据 password=""）。
- 同步协议：VERSION 3，account 消息新增 password（可选）。按现有 JSON 字段名与上限估算，一个 128 字符密码的 account 消息约 300–400 字节，远低于 1024 字节上限；500 个账号仍是逐条消息。
- 兼容策略（已定稿，见协议文档「版本兼容矩阵」）：手环解析 v2/v3 同步消息，v2 无密码；新版手机发 v3，旧手环直接忽略，手机 8 s 无 ack 提示「手环应用版本过低」；不实现 upgrade_phone 回包（旧手环无法回）。

### 3.2 安全

- 威胁模型：手环丢失/被他人戴走、旁人肩窥、手机被拿走、日志泄露。图案锁屏解决「拿到手环就能看码」；密码字段进一步扩大了泄露面。
- 必做：
  - 密码不写日志、不进错误信息、不出现在备份/调试导出；
  - UI 默认遮罩，10 秒自动恢复，离开页面立即恢复；
  - 图案只存 PBKDF2-SHA256 派生值 + 随机 salt（3^5=243 组合，PBKDF2 只能放慢离线穷举，不能提高熵；建议迭代 2 万次，需在 Vela JS 上实测耗时，太慢降到 1 万）；
  - 错误计数与临时锁定；
  - 关于页公开证书指纹，便于核对安装包。
- 可选增强（建议二期）：
  - **静态加密**：用手机端生成/下发的随机密钥加密 password（或全部 secret）后再落盘，**不要用 243 种组合的入口图案派生密钥**。好处是手环存储被拷走也读不出；代价是锁屏状态下无法后台同步、忘记图案会丢本地数据（需从手机重新同步），且 Vela JS 上 PBKDF2/AES 性能要实测。
  - 查看密码前再次输入图案（防肩窥），代价是操作变长。
- 我的建议：v2.0 先做「图案门禁 + 遮罩 + 不落日志」，静态加密作为可选项在 Q2 里定；不要在没有确认前把密码明文塞进 storage 就发布。

## 4. 交互与排版核对

- 480×336 下：3 张卡各 104px 高，主界面右侧功能条 56px，与 v1.0.4 一致；网格单格 116×73；详情页验证码 38px 仍有足够高度放进度条与说明。
- 锁屏三个图形键 118×118，横向 12px 间距，指腹大面积点按；5 个进度圆点 12px。手腕上操作需真机确认（尤其戴在手上时）。
- 所有手势都保留「按钮或手势二选一」：A-Z 按钮/网格、菜单按钮/右滑、返回/右滑、翻页/上滑下滑。
- 动效只做必要的：卡片翻页、网格翻页、锁屏错误抖动、密码显示倒计时；避免频繁重绘影响续航。
