# 安全说明

## 资产

- TOTP Secret：拿到即可生成验证码，等价于第二因素；
- 导出文件密码：可解密全部 secret；
- 两端签名私钥：决定谁能伪装成"同一个 App"与手环通信。

## 威胁模型

| 威胁 | 缓解 |
| --- | --- |
| 手机丢失 | 系统锁屏 + 应用私有存储；建议为 App 增加生物识别/系统应用锁（roadmap） |
| 手环丢失 | 手环快照含完整 secret；丢失后应撤销相关服务的 TOTP 并重新绑定，或清除手环应用数据 |
| 备份文件泄露 | 导出文件本身加密（Strong/Legacy）；导入后提示用户删除；密码不落盘 |
| 传输被窃听 | 依赖小米穿戴 BLE 链路的既有安全假设（与 BandOTP 相同）；不做额外端到端加密，避免虚假安全感 |
| 恶意 App 伪造同步源 | 手环快应用只接受来自同包名 + 同签名证书的手机 App（system.interconnect 的校验）；发布时保护 keystore |
| 调试日志泄露 secret | 发布构建禁止打印 secret/验证码；错误提示脱敏 |

## 明确不做

- 不在手环上做 PIN 解锁（手环无输入法，键盘输入体验差；且手环本身可设锁屏）；
- 不把 secret 上传任何服务器；
- 不做云备份/多设备同步。

## 发布前检查清单

- [ ] 替换 `signing/dev-release.jks`，使用你自己的 keystore，且 APK 与 .rpk 一致；
- [ ] 关闭调试日志中的敏感字段；
- [ ] 确认 .rpk / APK 的包名均为约定值；
- [ ] 在真机上验证：安装 → 导入 → 同步 → 断连后仍可查看验证码；
- [ ] 删除仓库中的测试备份文件与真实 secret。
