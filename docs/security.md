# 安全说明

## 资产

- TOTP Secret：拿到即可生成验证码，等价于第二因素；
- 账号密码：v2.0 起 Bitwarden 导入的 login.password 可同步到手环，详情页默认遮罩、点按显示 10 秒；
- 入口图案：手环/手机 App 的界面门禁，5 位图形序列；
- 导出文件密码：可解密全部 secret；
- 两端签名私钥：决定谁能伪装成"同一个 App"与手环通信。

## 入口图案（v2.0）

- 图案 = 5 位图形序列（三角 T / 方形 S / 圆形 C），共 3^5 = 243 种组合；
- 只保存 PBKDF2-HMAC-SHA256 派生值：16 字节随机 salt、1200 次迭代、输出 32 字节；不保存图案本身；
- 连续输错 5 次锁定 30 秒，之后每次再错锁定时间递增；手环冷启动要求图案，离开 2 分钟后再次要求；
- 手机端是信任根：手机可设置/修改/关闭图案，通过 mfa_pin_set / mfa_pin_clear 下发；手环端修改或关闭必须验证旧图案；
- 图案是**界面门禁**，不是静态加密密钥。能直接读取手环快照（含明文 secret）的攻击者不需要图案，因此不要把它当作数据加密。

## 威胁模型

| 威胁 | 缓解 |
| --- | --- |
| 手机丢失 | 系统锁屏 + 应用私有存储 + 入口图案（App 内）；建议再启用系统应用锁/生物识别 |
| 手环丢失 | 入口图案挡住随手翻看；但快照含完整 secret，丢失后应撤销相关服务的 TOTP 并重新绑定，或清除手环应用数据 |
| 旁人肩窥 | 验证码大字号但需进入详情才显示密码；密码遮罩 10 秒；图案需连续点按，不易一次看清 |
| 备份文件泄露 | 导出文件本身加密（Strong/Legacy）；导入后提示用户删除；导出密码不落盘 |
| 传输被窃听 | 依赖小米穿戴 BLE 链路的既有安全假设（与 BandOTP 相同）；不做额外端到端加密，避免虚假安全感；密码只在用户主动导入后随同步发送 |
| 恶意 App 伪造同步源 | 手环快应用只接受来自同包名 + 同签名证书的手机 App（system.interconnect 的校验）；发布时保护 keystore |
| 调试日志泄露 secret/密码 | 发布构建禁止打印 secret、验证码、密码、图案；错误提示脱敏 |

## 明确不做

- 不对快照做静态加密（需要先解决密钥托管与恢复，列为 roadmap；不要用固定密钥制造虚假安全感）；
- 不把 secret 或密码上传任何服务器；
- 不做云备份/多设备同步。

## 发布前检查清单

- [ ] 替换 `signing/dev-release.jks`，使用你自己的 keystore，且 APK 与 .rpk 一致；
- [ ] 关闭调试日志中的敏感字段（secret、验证码、密码、图案、hash/salt）；
- [ ] 确认 .rpk / APK 的包名均为约定值，版本号一致；
- [ ] 在真机上验证：安装 → 导入 → 同步 → 断连后仍可查看验证码；设置图案 → 冷启动/重锁 → 手环与手机均可改/关；
- [ ] 删除仓库中的测试备份文件与真实 secret。
